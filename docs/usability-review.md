## 发现及处理

| 优先级 | 已确认的问题 | 本次处理 |
|---|---|---|
| P1 | 忽略空白只更新消息，不改变实际高亮；用户看到的规则结果与编辑操作不一致 | 使用相同快照与原始行坐标计算规则结果，应用版本检查；规则持续到后续编辑并写入会话 |
| P1 | 人工锚点的请求标识直到完成才保存，多帧可能反复取消同一请求；ApplyHunks 未绑定请求版本 | 请求开始时保存标识，统一采用有版本保护且可取消的 ComputeRules，不再走无版本 ApplyHunks 路径 |
| P1 | 后台任务 defer cancel 后，异步 UI 回调再查 ctx 会把正常完成误判为取消 | 后台发布前检查错误，UI 回调通过 generation 与缓冲区版本拒绝失效结果；原生自动化等待导航真正可用 |
| P1 | 目录过滤后的结果与同步预览范围不同 | 当前过滤、属性或链接规则不受同步支持时明确拒绝预览，不扩大操作范围 |
| P1 | 单侧文件无法打开；向空白侧应用内容会多出末尾换行 | 缺失侧建立空缓冲区，创建保存拒绝覆盖既有目标；修复 MyGo 空缓冲区占位行逻辑并验证两方向换行保真 |
| P2 | 切换类型直接修改 kind，旧比较结果仍可能留在新页面 | 通过 selectKind 执行未保存保护并清除旧结果；普通路径输入也能识别两个目录 |
| P2 | 目录为居中宽按钮平铺，目录不可折叠，单侧内容无法检查 | 左右共享行布局、树层级、折叠、名称搜索、状态筛选、缺失侧留空、打开与返回 |
| P2 | *.txt 仅匹配根目录；会话恢复丢失过滤和编码选择 | 文件名模式递归匹配，带斜线模式匹配相对路径；树形显示保留父目录；会话保存规则，文本按检测编码读取 |
| P2 | 顶部堆叠所有入口和实现细节，核心按钮难找、窄窗口溢出 | 左侧导航、独立标题栏、对称路径面板、紧凑主工具栏、按侧保存、折叠高级选项；验证 900／1380 宽度 |
| P2 | 每扫描一个路径投递一次 UI 更新并保存所有进度字符串 | 运行应用按 50ms 限流，不保留无限增长的扫描进度切片 |

## 边界

这次交付只针对基本比较流程，不代表 Beyond Compare 全功能完成。目录目前按树形行浏览，但尚无完善的多选、右键操作、排序列及所有键盘操作；用户可直接打开单侧文件并逐块应用后保存。筛选条件下的同步暂时被阻止，完整规则同步仍待实现。真实系统 IME、Windows／Linux 运行、百万文件规模与共享目录竞争仍未验收。
